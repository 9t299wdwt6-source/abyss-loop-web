# Abyss Loop — отчёт сборки Prototype 61.0 RC7 QA Hotfix

**Версия:** `0.61.0`  
**Статус:** Release Candidate 7; Godot runtime не подтверждён в текущей среде.

## Этап 61 — адаптивные модальные окна и устойчивость доступности

- Длинный текст события, обучения, справки и подтверждения перенесён в ограниченный `ScrollContainer` с отключённой горизонтальной прокруткой и переносом строк.
- Заголовок и кнопки вариантов остаются вне прокручиваемой области текста. Это сохраняет доступ к решению при большом тексте и стандартной высоте окна.
- Высота области подробностей выбирается по длине текста и ограничивается текущей высотой viewport; окно настроек сохраняет отдельную общую вертикальную прокрутку формы.
- Сохранённый высокий контраст повторно применяется при перестроении экрана убежища, экрана экспедиции и модальных оверлеев. Изменение настроек продолжает влиять только на отображение.
- Добавлена `tests/ui_modal_responsiveness_regression.py` с десятью проверками ограничения высоты, прокрутки, доступности кнопок и повторного применения контраста.
- Добавлен `UI_ACCEPTANCE_RUNTIME_CHECKLIST_Prototype61.md` для ручной проверки на 1440×900 и 1920×1080 с масштабом 85%, 100% и 110%.
- Release preflight, packager, манифест, Windows launchers и регрессии обновлены до `0.61.0 / RC7`; исторические ZIP остаются неизменными.

## Этап 62A — надёжность статического QA-runner

- Добавлен общий subprocess runner `tools/test_process_runner.py`: каждый тест изолирован в process group; по тайм-ауту завершается всё дерево процессов, чтобы потомок с унаследованным stdout не мог зависнуть после завершения родителя.
- `tests/run_static_suite.py` сохраняет параллельный режим до четырёх workers по умолчанию; `ABYSS_LOOP_TEST_WORKERS=1..4` позволяет ограничить число потоков. По тайм-ауту изолированная process group завершается целиком.
- Добавлена `tests/static_suite_runner_regression.py` с настоящей проверкой процесса-потомка и bounded timeout. Оба Windows QA launcher выставляют ограничение до четырёх workers по умолчанию.
- Release packager и preflight требуют новый runner, его регрессию и `ROADMAP_CONTINUATION_STAGES29-62_RU.md`. Игровой код, механики, версия `0.61.0` и идентичность профиля не менялись.

**Статус:** это QA hotfix RC7, а не новая игровая версия. Полный статический прогон необходимо подтвердить после изменения runner; Godot 4.7.2 runtime и ручная приёмка остаются незакрытыми.

После обновления QA-runner полный набор повторно завершился **70/70 PASS**; актуальный отчёт включён отдельно в комплект выдачи.


## Этап 62B — общая очистка процессов для runtime release gate

- `tools/run_runtime_gate.py` использует `tools/test_process_runner.py`, чтобы каждый этап gate выполнялся в отдельной process group и весь процессный потомок завершался по тайм-ауту. Это закрывает разницу между надёжностью Python suite и Godot runtime gate.
- Добавлена `tests/runtime_gate_process_cleanup_regression.py` с проверками normal exit, controlled nonzero exit и timeout с потомком, который наследует stdout.
- Тест добавлен в обязательные файлы независимого preflight и упаковщика, а также в регрессию контракта релиза/архива.
- Функциональная проверка этой доработки: **3/3 PASS** (включая tree cleanup за ~2,5 секунды).
- После изменения повторно выполнен полный набор: **71/71 PASS за 43,34 с**; независимый release preflight: **7/7 PASS**; независимый аудит ZIP: **7/7 PASS**. Два архива, упакованные из неизменённого дерева, совпали по SHA-256. Godot 4.7.2 runtime и ручная приёмка остаются незакрытыми; статус остаётся RC7 QA hotfix, версия `0.61.0`.
