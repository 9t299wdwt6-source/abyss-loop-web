# Abyss Loop — Stage68B: телеметрия реальных забегов для Stage64B

- **База:** Stage68A, проект `0.61.0`; Stage68A ZIP не изменён.
- **Цель:** сделать этап реального балансного замера воспроизводимым, не заменяя игру офлайн-моделью.
- **Игровая телеметрия:** локальный журнал завершённого забега теперь может хранить версию схемы измерений, время работы процесса экспедиции, стартовые и конечные параметры героя, ресурсы профиля до оплаты контракта, комиссию, идентификаторы экипировки, количество размещений на дороге/ландшафте, длину маршрута и число обработанных шагов.
- **Совместимость:** поля являются дополнительными; старые активные снимки без baseline остаются помечены `legacy_partial`, значения стартовых характеристик не выдумываются. Формат версии активного snapshot оставлен `4`, новые поля опциональны.
- **Приватность:** измерения остаются в локальном сохранении. Нет сетевых запросов, удалённой аналитики или автоматической отправки отчётов.
- **Анализатор:** `tools/real_run_balance.py` читает локальный save-envelope или JSON с `runs`/`expedition_history`, исключает невалидные и дублирующиеся строки, разбивает данные по версии/сложности/модификатору/режиму и создаёт Markdown-отчёт.
- **Тесты:** целевая регрессия `tests/real_run_balance_capture_regression.py` — 17/17 PASS на синтетических fixtures; полный независимый Python-набор — **80/80 PASS**. Это статические/исходные проверки, не реальные игровые забеги.
- **Статус Stage64B:** всё ещё ОТКРЫТ для пользовательского баланса. Добавляется отдельный CI-сценарий пяти автоматизированных забегов на Godot 4.7.2. Его `automated_engine_run` телеметрия — QA-выборка движка и not human playtest; она не заменяет пользовательские прохождения. Синтетические fixtures не подменяют игровые данные.
- **Runtime:** не подтверждён: исполняемый Godot 4.7.2 отсутствует, скачать GitHub-бинарник из контейнера не удалось из-за DNS.
