# Abyss Loop — ручная приёмка управления клавиатурой (Prototype 51)

Проверять в Godot 4.7.2 на чисто распакованном архиве `AbyssLoop/`. Этот чек-лист не заменяется Python-регрессиями.

## Фокус на обычных экранах

- [ ] После запуска без сохранённого забега фокус виден на поле выбора режима; при сохранённом забеге — на «Продолжить экспедицию».
- [ ] Tab проходит элементы подготовки в понятном порядке: режим → сложность → модификатор → seed → контракт → начало экспедиции → остальные действия. Shift+Tab проходит в обратном направлении.
- [ ] У каждой кнопки, списка, поля seed, ползунка громкости и переключателя доступности есть заметная контрастная рамка фокуса.
- [ ] Enter активирует кнопку; стрелки меняют выбранное значение OptionButton/ползунка; ввод seed не запускает глобальные игровые команды.
- [ ] Быстрые двойные клики/повторная клавиатурная активация одной кнопки в пределах 180 мс выполняют команду только один раз.
- [ ] Esc в поле seed сначала снимает фокус и не активирует никакую игровую команду.
- [ ] На экспедиции начальный фокус находится на паузе; Tab проходит кнопки скорости, возврата и руку тайлов. В руке тайлов выбранную карту можно активировать клавиатурой; размещение на клетке маршрута остаётся отдельным действием карты.

## Модальные окна и безопасные решения

- [ ] При открытии обычного окна фокус перемещается внутрь него; Tab и Shift+Tab циклически проходят только элементы окна, не попадая в элементы фона.
- [ ] После закрытия окна фокус возвращается к элементу, из которого окно вызвали, если тот всё ещё существует. При смене экрана фокус переходит на главное действие нового экрана.
- [ ] В подтверждениях по умолчанию выделен безопасный вариант («Отмена», «Оставить как есть», «Продолжить путь» и т. п.), а не удаление/сброс. Enter не должен случайно уничтожать предмет или прогресс.
- [ ] Esc и F1 не закрывают и не вытесняют обязательные решения события/выбора перка и подтверждения разбора; для завершения решения требуется выбрать действие.
- [ ] Исследования, арсенал, журнал кампании, справка, экран результата и debug-панель (только debug build) полностью доступны последовательной навигацией и возвращают фокус корректно.
- [ ] В настройках Tab последовательно проходит ползунки и переключатели; Esc закрывает окно и восстанавливает прежнее состояние паузы.

## Регрессия и сборка

- [ ] Проверить разрешения 1440×900 и 1920×1080: видимый фокус не обрезается панелями, а длинные окна остаются прокручиваемыми.
- [ ] Запустить `RUN_TESTS_WINDOWS.bat`.
- [ ] Запустить `RUN_RELEASE_GATE_WINDOWS.bat` с Godot 4.7.2. Не объявлять пакет runtime-tested, если любой gate не прошёл.
- [ ] Полностью пройти одну экспедицию клавиатурой там, где взаимодействие не требует точного выбора клетки мышью, и записать все несоответствия.

Статус при подготовке Prototype 51: исходники и Python-регрессии проверены; Godot runtime/визуальная приёмка требуют запуска на целевой Windows-системе.
