# Abyss Loop — Stage 81: runtime checklist баланса лута

Эта проверка обязательна перед признанием Stage81 runtime-tested. Выполнять на чистой копии проекта в Godot 4.7.2 stable и на точном ZIP/fingerprint Stage81.

## A. Импорт и запуск

- [ ] Чистый импорт не выдаёт ошибок парсинга GDScript, отсутствующих ресурсов или autoload.
- [ ] Основная сцена открывается без ошибок в Output.
- [ ] Запустить новый профиль и начать экспедицию; открыть панель прогноза добычи.
- [ ] В UI отображаются раздельно шанс предмета и распределение качества «если предмет выпал».

## B. Выпадение предмета и источник

- [ ] Обычный враг начинается с 18% шанса предмета при нулевых бонусах.
- [ ] Элита имеет минимум 45% и не получает принудительный ранг `Элитная` для каждого дропа.
- [ ] Тайник начинается с 35%, а максимальные бонусы не поднимают шанс выше 85%.
- [ ] Босс даёт одну гарантированную специальную награду и не расходует заряды эха/обычные подготовленные бонусы как обычный дроп.
- [ ] Неудачный бросок не расходует `echo_item_charges`, `pending_item_drop_bonus` или `pending_item_rarity_bonus`.
- [ ] Успешный обычный/элитный/тайниковый дроп расходует соответствующие подготовки ровно один раз.
- [ ] Предмет попадает в начало рюкзака, не экипируется автоматически и получает стабильный `drop_source`.

## C. Распределение редкости и баланс

- [ ] При нулевом бонусе forecast показывает 70,0% обычного, 24,0% редкого, 5,2% эпического и 0,8% реликтового качества.
- [ ] С установленным предметом на редкость меняется только его действующий `rare_find_bonus`; предмет в рюкзаке не влияет на прогноз.
- [ ] Подготовка дорожного тайла и бонусы источника суммируются с ограничениями; общий bias не превышает 25 п.п.
- [ ] Пройти runtime assertions seeded-выборки (12 000 бросков без бонуса и 12 000 с максимальным bias) и сохранить лог.
- [ ] Убедиться, что более высокое качество остаётся более редким и максимальная подготовка не делает реликвии частыми.
- [ ] Элитная вещь сохраняет фактически выброшенный ранг и отдельно получает ограниченную премию параметров.

## D. UI, сохранение и веб

- [ ] В подробной подсказке правильно показаны шансы обычного врага, элиты, тайника и боссовое исключение.
- [ ] Журнал честно различает шанс предмета и условную вероятность качества при успешном дропе.
- [ ] Сохранить checkpoint с зарядами эха и подготовленными бонусами, перезапустить игру и проверить их восстановление.
- [ ] Проверить откат при принудительной ошибке записи снимка; предмет или заряд не должен дублироваться/теряться.
- [ ] Пройти viewport 1440×900, 1920×1080 и 390×844; сохранить screenshots панели добычи и убежища.
- [ ] Только после обновления web export из точного Stage81 commit запустить Chromium smoke, gameplay acceptance, reload/resume и сравнить fingerprint опубликованной версии. Stage68C screenshots не считать приёмкой Stage81.

## Статус

Пока галочки runtime не поставлены, считать этот этап source-tested only. Не называть его runtime-tested, не утверждать, что Web build содержит Stage81, и не деплоить автоматом старый экспорт.
