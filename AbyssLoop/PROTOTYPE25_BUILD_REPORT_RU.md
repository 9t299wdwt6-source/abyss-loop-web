# Abyss Loop — отчёт сборки Prototype 25

## Краткий итог

Prototype 25 — первый тематический проход «Эхо глубин». Архив построен на основе проекта Prototype 24; прошлый ZIP не перезаписывается. Игровые идентификаторы и численные коэффициенты сохранены; изменения контента в `ContentRegistry` затрагивают только названия и цвета отображения.

## Изменено

- Фоновый ресурс `assets/background/abyss_pixel_backdrop.png`, 480×300: вид на террасы, водопады, мосты и руины многослойной бездны без текста и персонажей.
- Подложка интерфейса и карты использует nearest-neighbour фильтрацию и сохраняет пропорции.
- Панели, рамки и кнопки переведены на угловатый каменно-мшистый стиль; добавлены базальтовая, мшистая, янтарная и кристаллическая палитры.
- Маркеры маршрута стали квадратными, с малыми блочными пиктограммами по типу узла/тайла.
- Маркер героя отрисовывается пиксельными прямоугольниками — капюшон, плащ, рюкзак и фонарь; силуэт оригинальный.
- Тематизированы первые имена местности, тайлов, противников, боссов и построек. Их стабильные ID не менялись.
- Добавлены `THEME_BIBLE_RU.md`, обновлённая дорожная карта, расширенная матрица ручного приёмочного тестирования и статический тест `theme_art_regression.py`.
- В GDScript smoke test добавлена проверка загрузки фоновой текстуры и её размеров.

## Результат проверки

- **24/24 Python static/regression checks прошли** через `python tests/run_static_suite.py`.
- ZIP целостность проверена после создания; проект распаковывается.
- **Godot Runtime не запускался в среде сборки:** исполняемый файл Godot 4.7.2 отсутствует, а попытка обратиться к GitHub для загрузки движка не удалась из-за недоступности DNS. Следовательно, компиляция GDScript, выполнение `tests/smoke_test.gd` и визуальный осмотр в редакторе не подтверждены этой сборкой.

## Ручной приёмочный прогон в Godot 4.7.2

1. Открыть `project.godot` и запустить F5.
2. Проверить убежище при 1440×900 и 1920×1080: фон виден по краям/сквозь панели, текст читается, ничего не выходит за окно.
3. Начать экспедицию: карта показывает ту же панораму; узлы квадратные; пиктограммы узлов и маркер героя различимы.
4. Проверить движение и клик по узлам: логическое положение героя, метка боя/босса и возможность установки тайла не изменились.
5. Запустить `RUN_TESTS_WINDOWS.bat` с установленным Godot в `PATH` или задать переменную `GODOT_EXE`. Успешным результатом будет завершение всех Python-проверок и Godot smoke test с кодом 0.
6. Пройти полный цикл: начало → бой/событие → получение добычи → возвращение/поражение → убежище → сохранение и возобновление.

Статические проверки подтверждают наличие ресурсов и охранные условия в исходниках, но не являются доказательством фактической компиляции/игрового прогона.
