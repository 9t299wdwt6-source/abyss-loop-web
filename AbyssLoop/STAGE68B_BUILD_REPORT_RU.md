# Stage68B — отчёт разработки: локальный сбор и анализ реальных забегов

## Что изменено

### Сбор данных в ExpeditionManager

- Добавлен счётчик секунд процессного времени экспедиции. Он учитывает время, пока игра работает, включая экран решения/паузу, но не считает время после закрытия процесса. Значение сохраняется в checkpoint и восстанавливается при продолжении.
- В стартовом baseline фиксируются HP/макс. HP/атака/защита, баланс профиля до оплаты контракта и ID трёх предметов экипировки. Перед завершением записываются конечные параметры, потраченная комиссия контракта, время, число дорожных и ландшафтных размещений, длина маршрута и обработанные шаги.
- Поля добавлены в компактный bounded campaign history. Нет записи в сеть, отдельного фона или изменения игрового баланса.
- Старые активные snapshots без `run_baseline` маркируются `telemetry_schema=0` / `legacy_partial`; инструмент не притворяется, что знает стартовые характеристики старого забега.

### Инструмент Stage64B

`tools/real_run_balance.py` принимает либо локальный Godot save-envelope с `data.expedition_history`, либо JSON-экспорт с массивом `runs` или `expedition_history`. Он проверяет ключевые поля и нецелочисленные/отрицательные метрики, исключает повторные `run_id`, разбивает группы по версии игры, сложности, модификатору и режиму, вычисляет только описательные медианы/частоты и показывает достаточность выборки.

Пример команды из корня проекта:

```bash
python tools/real_run_balance.py --input loop_roguelite_save.json --output real_run_balance_report.md --label "Stage68B" --godot-version "4.7.2.stable" --minimum-repeats 5
```

Для source fingerprint можно добавить `--source-fingerprint <64 hex>` только когда контрольная сумма действительно известна. Не указывайте выдуманный fingerprint.

## Проверки

- Целевая регрессия анализатора: **17/17 PASS** на синтетических данных.
- Полный регрессионный набор: **80/80 PASS**, все тестовые скрипты повторно выполнены по отдельности на финальном дереве; сводка и индивидуальные результаты сохранены в `tests/reports/STATIC_TEST_REPORT.txt`. `tests/run_static_suite.py` как агрегатор не объявляется пройденным.
- Release preflight проверяет документацию, анализатор и тесты; ZIP сверяется по CRC и побайтовому содержимому.
- Геймплейный баланс, награды, формулы боя, вероятности и цены не менялись.

## Ограничения и честный статус

- **Не runtime-tested.** Godot 4.7.2 не установлен. Попытка скачать binary с GitHub завершилась DNS error, поэтому GDScript-компиляция, работа `FileAccess`, восстановление checkpoint и сериализация новых полей не подтверждены движком.
- **Реальные замеры ещё не получены.** Все данные из тестов анализатора синтетические и используются только для проверки корректности инструмента. Статистический вывод о балансе не сформулирован.
- Не загружайте save-файл в публичные сервисы: локальный инструмент ничего не отправляет; для передачи отчёта достаточно Markdown-результата, а не всей профильной папки.

Следующий обязательный шаг — запустить Godot 4.7.2, проверить новую запись/восстановление полей и провести контролируемые реальные забеги Stage64B.
