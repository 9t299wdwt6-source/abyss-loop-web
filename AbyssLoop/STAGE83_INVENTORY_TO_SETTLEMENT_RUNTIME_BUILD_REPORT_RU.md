# Stage 83 — Inventory-to-Settlement Runtime Acceptance

## Цель

The 12-item backpack end-to-end scenario covers real run APIs. Current status: runtime не подтверждён until Godot executes the isolated scene.

Связать уже существующие системы в один воспроизводимый интеграционный сценарий: добыча предмета → FIFO-рюкзак → экипировка → сохранение → восстановление → безопасный возврат/поражение → постоянные награды.

## Составлено

- `tests/inventory_settlement_runtime_acceptance.gd` — сценарий на производственных API, с двумя исходами экспедиции.
- `tests/inventory_settlement_runtime_acceptance_runner.tscn` — отдельная тестовая сцена.
- `tests/stage83_inventory_settlement_regression.py` — статические гарантии связности и безопасности.
- `tools/run_runtime_gate.py` — добавлен восьмой gate `Inventory-to-settlement runtime acceptance`.
- `tools/package_release.py` и `tools/release_preflight.py` — новая документация и runtime-сценарий стали обязательными файлами релиза.

## Сценарий проверяет

1. Изолированный профиль начинает реальную экспедицию фиксированным seed.
2. 12 уникальных предметов помещаются в рюкзак. Повтор уже существующего ID не меняет bag, счётчик вытеснений или пыль.
3. 13-й предмет вытесняет именно самый старый экземпляр и добавляет рассчитанное количество пыли.
4. Новый предмет вручную экипируется. Один ID не может одновременно находиться в экипировке и рюкзаке.
5. Снимок сохраняется и восстанавливается вторым `ExpeditionManager`; проверяются порядок рюкзака, слоты, seed и накопительные поля.
6. При возврате переносимые предметы и экипировка попадают в арсенал; вытесненная вещь туда не попадает, а пыль начисляется один раз.
7. Повтор settlement с тем же run ID не дублирует ресурсы, историю, завершение или предметы.
8. Во второй экспедиции поражение оставляет экипировку, но не сохраняет свободные предметы из рюкзака; пыль удерживается по правилу поражения.

## Статус

**runtime не подтверждён.** Source-level тест не подменяет исполнение GDScript. Выполнение требует официального Godot 4.7.2 stable в среде с доступом к бинарному файлу. Тест специально отказывается запускаться без `ABYSS_LOOP_RUNTIME_QA=1`, чтобы не затронуть пользовательское сохранение при ручном запуске.

Обычная сборка Stage 83 остаётся release candidate, а не runtime-tested архивом. Runtime gate теперь блокирует такую маркировку, если один из восьми шагов, включая этот сценарий, не проходит.
