# Stage 83 — ручная проверка инвентаря и завершения экспедиции

Окружение: **Godot 4.7.2 stable**, копия проекта с отдельным профилем. Не запускать сценарий вручную с обычным пользовательским профилем; автоматический тест требует `ABYSS_LOOP_RUNTIME_QA=1`.

The `defeat` path is included alongside the safe-return path.

## Автоматический runtime acceptance

- [ ] Сценарий начинает реальную экспедицию на фиксированном seed.
- [ ] 12 уникальных вещей заполняют рюкзак, повторный ID отклонён без побочного эффекта.
- [ ] 13-я вещь вытесняет oldest/FIFO запись; счётчик и Пыль утраченных вещей изменяются ровно один раз.
- [ ] Предмет экипируется из рюкзака без дублирования экземпляра.
- [ ] Сохранение и восстановление сохраняют порядок, экипировку, seed и накопительную пыль.
- [ ] Возврат сохраняет экипированные и переносимые вещи; вытесненную вещь не сохраняет.
- [ ] Повтор settlement с тем же run ID не создаёт дополнительных наград.
- [ ] Поражение сохраняет только экипировку и применяет долю удержания ресурсов.
- [ ] Ни один ID не находится одновременно в рюкзаке и в экипировке.
- [ ] Runtime gate выдаёт PASS только при успешном завершении сценария.

## Ручная визуальная проверка

- [ ] В окне экспедиции видны 12 ячеек рюкзака, редкости и сравнение предметов.
- [ ] Экипировка срабатывает при перетаскивании и быстром экипировании.
- [ ] При заполненном рюкзаке игрок видит, что именно вытеснено, и получает понятную обратную связь о пыли.
- [ ] Экран итогов корректно показывает добычу, удержанную пыль и потерянные предметы при поражении.
- [ ] Повторная загрузка веб-версии восстанавливает тот же рюкзак и экипировку; старый Stage 68C не считается доказательством.

В этой сборке автоматический GDScript сценарий добавлен, но до запуска на Godot 4.7.2 пункты не считаются подтверждёнными.
