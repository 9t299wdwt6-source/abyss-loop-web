# Runtime-чек-лист Stage 86 — процедурные дорожные петли

**Целевая среда:** Godot 4.7.2 stable; затем свежий Web export с Chromium. Чек-лист не отмечается пройденным по статическим тестам.

## Запуск и геометрия

- [ ] Проект открывается в Godot без ошибок парсинга GDScript, missing resource и type inference.
- [ ] Запустить `tests/smoke_test.gd`; сохранить полный лог, подтвердить Stage86 assertions.
- [ ] Для каждой семьи `classic_ring`, `narrow_ring`, `deep_descent`, `fractured_loop` посмотреть минимум три seed, включая seed `1`, `42` и `123456` где применимо.
- [ ] При одинаковом seed видимый контур повторяется; при разных seed у каждой семьи видно несколько вариантов.
- [ ] Каждый контур имеет 34 клетки, дорога занимает одну клетку в ширину, повороты/отводы ортогональны, петля полностью замкнута.
- [ ] Проверить отсутствие бокового слипания и визуального среза в месте каждого наружного отвода; герой проходит маршрут без диагональных скачков.
- [ ] Проверить карту на окнах 620×420, 900×600, 1280×720, 1440×900, 1920×1080, а также на компактных размерах 300×350 и 390×844.

## Размещение и секторная логика

- [ ] Нажатие на центр/край дорожной клетки выбирает дорогу, а не клетку ландшафта.
- [ ] Ландшафт запрещено размещать на дорожных координатах текущего seed.
- [ ] Клетки `roadside` принимают только карту придорожной зоны; `landscape` не принимает клетку дороги или придорожной полосы.
- [ ] Предпросмотр размещения, реальная установка и сохранённый `route_index` используют один и тот же seed/profile.
- [ ] Соседние синергии и эффекты сектора остаются корректными вокруг наружных отводов и в месте замыкания контура.

## Сохранения и совместимость

- [ ] Создать новую экспедицию, сохранить `route_geometry_seed`, закрыть и возобновить; видимая петля и размещённые карты совпадают до/после загрузки.
- [ ] Повторить для нескольких разных seed и семей маршрута.
- [ ] Загрузить snapshot, созданный до Stage86 и не содержащий `route_geometry_seed`: сохраняется прежний прямоугольный контур и все карты остаются на прежних клетках.
- [ ] Проверить, что валидатор отклоняет сохранение с современной ландшафтной картой, чьи `m:col:row` координаты попадают на дорожную клетку текущего seed.
- [ ] Запустить `tests/save_system_regression_runner.tscn`; сохранить результат и предупреждения.

## Web export и браузер

- [ ] Создать свежий Web export из текущего исходного проекта; не использовать историческую опубликованную сборку.
- [ ] Открыть `index.html` через HTTP-сервер, подтвердить запуск WebAssembly без JS/console ошибок.
- [ ] Повторить размещение дорожных/ландшафтных карт на desktop viewport и 390×844.
- [ ] Перезагрузить браузер после размещения и проверить восстановление экспедиции с тем же контуром.
- [ ] Записать version/hash экспортированных файлов и приложить скриншоты viewport 1440×900 и 390×844.

## Решение по этапу

- [ ] Все проверки выше выполнены на точной сборке Stage86.
- [ ] В отчёте указаны версия Godot, результаты smoke/save/reload, браузер и источник Web export.
- [ ] При любой ошибке компиляции/рантайма/контура статус Stage86 остаётся «runtime не подтверждён» до исправления и повторного полного прогона.
