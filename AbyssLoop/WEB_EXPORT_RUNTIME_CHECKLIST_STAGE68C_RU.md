# Stage68C — чек-лист runtime-приёмки Web-сборки

Целевой движок: **Godot 4.7.2 stable**. Целевой графический API: **WebGL 2.0**. Все пункты ниже должны быть проверены на реальном экспортированном `index.html`, прежде чем считать Web-релиз принятым.

## A. Создание и размещение

- [ ] Запустить `tools/export_web.sh` в Linux x86_64 либо экспортировать проект из Godot GUI через preset `Web`.
- [ ] Подтвердить версию движка и успешный импорт всех ресурсов без ошибок.
- [ ] Убедиться, что `index.html`, `index.js`, `index.wasm` и `index.pck` существуют и не пусты.
- [ ] Запустить `python3 tools/web_export_preflight.py --mode build --root ../AbyssLoop_WebExport` и получить ноль FAIL.
- [ ] Запустить `python3 tools/web_browser_smoke_test.py --directory ../AbyssLoop_WebExport --screenshot /tmp/abyssloop-web.png --report /tmp/abyssloop-web.json`.
- [ ] Проверить, что HTTP-ответ WASM содержит MIME `application/wasm`, нет ошибок JS/console, а WebGL 2 доступен.

## B. Публикация и браузеры

- [ ] Загрузить исходники в GitHub repository на `main`.
- [ ] В Settings → Pages выбрать Build and deployment → Source: GitHub Actions.
- [ ] Запустить workflow `Abyss Loop Web Export and Browser QA`; проверить import, export и Chromium smoke-test.
- [ ] Только после успешного job получить URL из шага `deploy-pages`.
- [ ] Открыть опубликованный сайт в актуальном Chrome/Firefox/Edge; не полагаться только на локальный `file://` URL.
- [ ] Открыть сайт в Safari на iPhone и проверить портретный/альбомный режим, экранную клавиатуру/сенсорный ввод и изменение размеров canvas.

## C. Игровые сценарии после появления ссылки

- [ ] Первый запуск: главное меню открывается, нет зависания на загрузке ресурсов.
- [ ] Начать экспедицию, выбрать карту и разместить её на дорожном узле.
- [ ] Разместить тайл на ландшафте; убедиться, что блокировка/лимиты и подсветка совпадают с моделью.
- [ ] Пройти обычный бой и проверить эффекты статуса и подписи ролей врагов.
- [ ] Активировать синергию и проверить подсказку первого часа.
- [ ] Открыть событие, принять решение и убедиться, что интерфейс возвращается в правильное состояние.
- [ ] Дойти до элитного противника/босса, увидеть предупреждение атаки и завершить бой.
- [ ] Сохранить игру, перезагрузить страницу и проверить продолжение; отдельно проверить, что данные локального хранилища сохраняются для того же origin.
- [ ] Очистить storage только на тестовом профиле и убедиться, что поведение пустого сохранения корректно.
- [ ] Выполнить второй запуск по тому же URL и сравнить поведение с первым.

## D. Release gate

- [ ] Нет критических ошибок в консоли браузера.
- [ ] Все обязательные runtime-ресурсы возвращаются с успешным HTTP-статусом.
- [ ] Нет критических ошибок в отладочном выводе движка.
- [ ] Проверены mouse и touch; canvas не перекрывает интерактивные области.
- [ ] Проверены сохранения и контрольная точка.
- [ ] Отчёты, скриншот и JSON smoke-test приложены к версии.
- [ ] Отдельно зафиксировано, что автоматический smoke-test не покрывает баланс и всё прохождение игры.

**Текущий статус:** Godot 4.7.2 runtime не выполнен; WebGL 2.0 в фактической сборке пока не проверен; публичный URL не опубликован.
