# Stage 86 — процедурная геометрия дорожных петель

**Проект:** Abyss Loop `0.61.0`  
**Статус:** локальная development-сборка; не runtime-tested и не опубликованный релиз.

## Цель

Заменить четыре всегда-прямоугольных контура вариативными, но детерминированными дорожными петлями. При этом сохранить 34 дорожные клетки, квадратную сетку 19×14, единый источник геометрии для отрисовки/размещения и совместимость старых снимков экспедиции.

## Что изменено

1. **Геометрия централизована в TileSystem.** `RouteView` больше не строит дорожный периметр отдельно. Отрисовка, hit test, проверка размещения ландшафта, прогноз размещения, расчёт сектора и проверка снимка используют `get_road_grid_coordinates_for_seed(...)`.
2. **Добавлены детерминированные контурные варианты.** Положительный `route_geometry_seed` выбирает семью профиля, вариант базового контура и ограниченные наружные обходы. При изменении seed геометрия меняется повторяемо, а форма по-прежнему является единственной замкнутой ортогональной петлёй.
3. **Бюджет дороги всегда равен 34 клеткам.** Четыре режима используют разные сочетания базового периметра и отводов: 30 + 2 shallow detours, 30 + один более глубокий detour, 32 + один shallow detour или 28 + три shallow detours. В месте каждого отвода средняя клетка базовой дороги удаляется, чтобы не оставлять короткий параллельный контакт.
4. **Геометрия валидируется до возврата.** Проверяются ровно 34 уникальные координаты, отступ от внешнего края в одну клетку, ортогональная непрерывность с замыканием последней клетки на первую и отсутствие посторонних боковых соединений между несоседними позициями. При внутренней ошибке включён безопасный резервный фиксированный контур.
5. **Seed сохраняется вместе с экспедицией.** Новые забеги используют `route_geometry_seed`, полученный из seed забега, и записывают его в снимок. Загрузка старого снимка без этого поля устанавливает seed `0`, который сохраняет прежнюю прямоугольную геометрию. Так уже сохранённые клетки и их `route_index` не перемещаются неожиданно после обновления.
6. **Валидация согласована с новым контуром.** Запрещено размещать ландшафтную карту на реальной дорожной клетке текущего seed. Придорожная зона, назначение сектора и предпросмотр получают тот же seed, что и вид карты; ключ кэша карты включает его.
7. **Регрессионные и релизные проверки расширены.** Добавлены Stage86 source/numerical regression, runtime-smoke утверждения, документация ручной приёмки и обязательные Stage86 артефакты независимого release preflight.

## Результаты автоматических проверок

- Stage 86 procedural contour regression: **17/17 PASS**.
- Python reference/stress model: **2 048 сценариев** (512 seed на каждую из четырёх семей контуров). Все модели дают 34 уникальные ортогональные клетки, замкнутую петлю, безопасный отступ, отсутствие лишних касаний и много вариантов для каждой семьи.
- Полный Python static/regression suite: **112/112 PASS**.
- Предыдущие проверки Stage84 и Stage85 остаются в наборе проекта, чтобы не потерять гарантии квадратной сетки и всех 232 клеток вне дороги.

**Ограничение доказательства:** численные сценарии выполняют независимую Python-модель и проверяют связь GDScript с единой геометрией через source guards. Они не исполняют сам GDScript. Соответствующие утверждения добавлены в Godot smoke tests, но сам движок в этой среде запустить не удалось.

## Runtime и веб-сборка

**Godot 4.7.2 runtime не подтверждён.** Бинарный файл движка отсутствует; попытка загрузить его не удалась из-за недоступного сетевого DNS в среде. Также не удалось открыть текущий GitHub Pages URL через доступный веб-инструмент. Поэтому реальная отрисовка, клики/касания, компиляция GDScript, сохранение/возобновление в движке и свежий Web export не объявляются проверенными. Для них создан отдельный `PROCEDURAL_ROUTE_CONTOURS_RUNTIME_CHECKLIST_STAGE86_RU.md`.

## Следующее действие

Пройти Stage86 runtime-чек-лист на Godot 4.7.2 stable, включая запуск через браузер свежего Web export. Особое внимание уделить старым сохранениям без `route_geometry_seed`, воспроизводимости карты после перезапуска и корректности hit-test у наружных отводов.
