# Руководство: собрать реальные данные баланса Stage64B

## 1. Получить повторяемые прохождения

1. Используйте один и тот же ZIP Abyss Loop и Godot 4.7.2 stable на протяжении одной серии.
2. Зафиксируйте сложность, модификатор, режим экспедиции и контракт. Для начального сравнения не меняйте одновременно несколько факторов.
3. Сделайте не менее 5 забегов для одного сочетания настроек и используйте минимум 3 разных seed. Для проверки конкретного случайного сценария можно дополнительно повторить один seed несколько раз.
4. Записывайте UI/runtime-ошибки отдельно. Не считайте зависший/ошибочный запуск обычным игровым поражением.
5. Не меняйте баланс до тех пор, пока проблема не повторится и на сопоставимой выборке не будет исключена ошибка UI/runtime.

## 2. Скопировать локальную историю

Откройте сохранение игры `loop_roguelite_save.json` из пользовательской папки Godot. Точный каталог зависит от ОС и имени пользовательского профиля; найдите его через `OS.get_user_data_dir()` в Godot или в диагностике профиля. Сделайте **копию** файла. Не редактируйте оригинал и не заменяйте им сохранение.

Внутри стандартного сохранения история находится в `data.expedition_history`. Инструмент также принимает JSON-экспорт вида:

```json
{
  "metadata": { "build_label": "Stage68B", "godot_version": "4.7.2.stable" },
  "runs": []
}
```

Не заполняйте демонстрационный массив синтетическими данными, если нужен отчёт о реальных прохождениях.

## 3. Построить отчёт локально

Из корня проекта:

```bash
python tools/real_run_balance.py --input loop_roguelite_save.json --output stage64b_report.md --label "Abyss Loop Stage68B" --godot-version "4.7.2.stable" --minimum-repeats 5
```

При наличии фактического SHA-256 исходников разрешено добавить `--source-fingerprint`. Отчёт группирует записи по версии, сложности, модификатору и режиму; дубли `run_id` исключаются. Время прохождения используется только для новой схемы Stage68B.

## 4. Что передавать для анализа

В отчёте нужны число забегов и seed, outcome, циклы, боссы, победы, ресурсы получены/сохранены/потеряны, время процесса, HP и размещения. Сам save может содержать весь прогресс пользователя — передавайте только необходимый отчёт, если нет отдельной причины передавать данные профиля.

## 5. Что отчёт не делает

Инструмент не симулирует бой, не чинит сохранение, не изменяет исходные файлы, не отправляет аналитику и не выдаёт автоматический verdict «баланс хороший/плохой». Пять забегов и три seed — лишь минимальный ориентир для первичного просмотра, не доказательство статистической значимости.
