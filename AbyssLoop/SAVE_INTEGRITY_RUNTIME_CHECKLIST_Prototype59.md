# Чек-лист runtime-проверки сохранений — Prototype 59

Запускать на Godot 4.7.2 в тестовой копии проекта и с изолированным `user://` профилем. Этот список не разрешает менять или удалять пользовательское сохранение.

- [ ] Создать профиль и выполнить два сохранения; проверить, что primary и backup читаются, а новый envelope содержит `integrity.algorithm = sha256` и 64 hex-символа checksum.
- [ ] Изменить одно значение в `data` без пересчёта checksum; при загрузке изменённая primary должна быть отвергнута, валидная backup должна быть выбрана.
- [ ] Переставить ключи JSON-словаря без изменения значений; canonical checksum должен оставаться той же.
- [ ] Удалить/повредить primary при наличии валидной backup; восстановление должно сообщать соответствующий `last_load_status` и не терять backup.
- [ ] Загрузить контрольные версии 1, 2 и 3 без `integrity`; миграция не должна сбрасывать существующий прогресс.
- [ ] Проверить отказ неизвестного алгоритма, неверную длину checksum и неверную checksum.
- [ ] Экспортировать сохранение, импортировать его в тестовый профиль и проверить совпадение данных.
- [ ] Прервать процесс после создания temporary-файла в тестовом профиле; проверить восстановление лишь валидной транзакции.
- [ ] После каждого сценария сверить ресурсы, исследования и состояние экспедиции, убедиться в отсутствии двойных наград.

**Ограничение:** Python статические регрессии проверяют исходные контракты; этот чек-лист требует реального движка и не считается выполненным автоматически.
