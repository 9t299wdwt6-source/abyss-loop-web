# Ручная runtime-приёмка телеметрии Stage68B

## Подготовка

- [ ] Используется точный Godot **4.7.2 stable**.
- [ ] Перед изменениями сохранение скопировано; основной профиль не используется тестовым аудитом.
- [ ] Записаны build/ZIP label, fingerprint если получен, seed, difficulty, modifier, mode и contract.

## Новая экспедиция

- [ ] Стартовая история/снимок получает `telemetry_schema=1`.
- [ ] `run_elapsed_seconds` возрастает в процессе работы игры и попадает в autosave.
- [ ] После закрытия и запуска заново таймер продолжает увеличиваться от сохранённого значения, не сбрасывается.
- [ ] В событии или на паузе время считается по принятой спецификации процесса; после закрытия игры время не добавляется.
- [ ] В итоговой истории есть start/end HP, max HP, атака/защита, стартовый баланс до контракта, комиссии контракта, ID loadout, дорожные/ландшафтные размещения и processed steps.
- [ ] Возврат и поражение сохраняют корректные ресурсы; telemetry не изменяет итоговую награду.

## Совместимость и безопасность

- [ ] Загрузить checkpoint, созданный предыдущей сборкой без baseline; он не выдумывает стартовые характеристики и помечается `legacy_partial`.
- [ ] История ограничена максимум 50 записями; повторная обработка одного `run_id` не создаёт дубль.
- [ ] Повреждённые/лишние telemetry-поля не дают принять невалидное сохранение.
- [ ] Сбор данных полностью локальный; сетевых вызовов нет.

## Реальные балансные прогоны

- [ ] Для выбранного набора настроек пройдены ≥5 реальных экспедиций с ≥3 разных seed.
- [ ] Для повторяемой проблемы проведены дополнительные идентичные повторы.
- [ ] Выполнен `tools/real_run_balance.py` на копии реальной истории; исходный save не меняется.
- [ ] Офлайн-модель Stage64A отдельно помечена как модель, а не часть реального набора.

**Статус сейчас:** пункты не отмечаются пройденными до ручного выполнения на Godot 4.7.2.
