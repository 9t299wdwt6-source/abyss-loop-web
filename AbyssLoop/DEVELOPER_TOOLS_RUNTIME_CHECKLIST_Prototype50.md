# Abyss Loop — ручная приёмка инструментов разработчика (Prototype 50)

**Требуемая среда:** Windows, Godot 4.7.2 stable.  
**Статус:** подготовлено; вручную выполнить перед закрытием этапа 50.  
**Принцип:** диагностическая панель только читает игровое состояние и не должна менять сохранения.

## 1. Debug-сборка

- [ ] Запустить `AbyssLoop/project.godot` из редактора Godot 4.7.2.
- [ ] Убедиться, что в заголовке есть кнопка «Диагностика · F9».
- [ ] Нажать F9 и убедиться, что открывается затемнённая панель с независимой вертикальной прокруткой.
- [ ] Закрыть панель клавишей F9 и открыть повторно кнопкой.
- [ ] Нажать «Обновить»: данные обновляются, панель не закрывается.
- [ ] Нажать «Копировать отчёт», вставить в текстовый редактор и убедиться, что отчёт содержит версию движка, содержимое реестра и статус проверки.

## 2. Убежище и активная экспедиция

- [ ] Открыть панель в убежище. Отчёт явно сообщает, что активной экспедиции нет; панель не вызывает ошибки.
- [ ] Запустить обычную экспедицию с известным seed. Проверить соответствие seed, сложности, режима и модификатора выбранным значениям.
- [ ] Убедиться, что количество узлов и отметка замкнутого маршрута согласуются с картой.
- [ ] Во время боя проверить здоровье героя/врагов и список статусов, затем проверить отсутствие встречи после боя.
- [ ] Разместить ландшафтный тайл и проверить счётчики руки/поля.
- [ ] При выборе события/перка проверить соответствующий ожидающий выбор в диагностике.
- [ ] Сохранить и возобновить забег; сравнить seed, узел, цикл и состояние snapshot.
- [ ] После закрытия панели проверить, что ресурсы, seed, пауза и ход боя не изменились от самой диагностики.

## 3. Контент-валидатор и размер окна

- [ ] При штатном реестре убедиться, что валидатор показывает PASS и 0 ошибок.
- [ ] Проверить первые строки отчёта на читаемость и прокрутку на 1440×900 и 1920×1080.
- [ ] Проверить, что длинные сообщения не обрезаются горизонтальным скроллом.
- [ ] Не редактируя основной игровой профиль, протестировать сообщение о некорректной конфигурации в отдельной тестовой копии проекта; убедиться, что указан ID и причина.

## 4. Release build и регрессии

- [ ] В release-сборке кнопка диагностики отсутствует.
- [ ] F9 в release-сборке не открывает панель и не меняет состояние игры.
- [ ] Запустить `RUN_TESTS_WINDOWS.bat`.
- [ ] Запустить `RUN_RELEASE_GATE_WINDOWS.bat` в чистой изолированной копии с Godot 4.7.2.
- [ ] Пройти сценарии основной приёмочной матрицы; результаты зафиксировать отдельно от статических тестов.

## Критерий закрытия

Этап 50 закрывается только после успешной компиляции GDScript, smoke-теста, регрессии сохранений и ручного подтверждения панели в debug/release вариантах. Python PASS сам по себе не подтверждает эти пункты.
