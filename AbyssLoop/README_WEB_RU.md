# Abyss Loop — Web-версия и браузерная приёмка

В проект добавлен воспроизводимый Web-пайплайн на Godot 4.7.2 stable. **Это конфигурация и автоматизация экспорта, а не уже собранный WebAssembly-релиз.** Для появления настоящей ссылки надо хотя бы один раз выполнить экспорт и опубликовать статические файлы на хостинге.

## Почему выбран такой Web-профиль

- Рендерер `gl_compatibility`: единственный поддерживаемый метод рендеринга Godot 4 для Web/WebGL 2.0.
- Однопоточный экспорт (`variant/thread_support=false`): не требует заголовков COOP/COEP и проще размещается на игровых хостингах.
- Экспорт называется `index.html`; файлы `.js`, `.wasm` и `.pck` должны оставаться рядом и не переименовываться.
- Путь сохранений игры остаётся `user://`; проверка реальной устойчивости сохранений в браузере всё ещё входит в ручную runtime-приёмку.
- Включено обе опции сжатия VRAM для Desktop и Mobile ради более широкой совместимости браузеров.

Ограничения и настройки соответствуют руководствам Godot Web: https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html

## Linux x86_64: собрать локально

Установите `curl`, `unzip`, `sha256sum` и Python 3, затем из корня проекта выполните:

```bash
./tools/export_web.sh
```

Скрипт скачивает Godot 4.7.2 stable и архив шаблонов с официального сервера Godot, сверяет SHA-256 обоих архивов, импортирует проект и экспортирует его в `../AbyssLoop_WebExport/`. Исходный проект и ZIP-сборка не перезаписываются.

Для ручного экспорта Windows/macOS:

1. Установить Godot 4.7.2 stable и соответствующие export templates.
2. Открыть `project.godot`.
3. В Project → Export убедиться, что существует preset `Web` (он уже сохранён в `export_presets.cfg`).
4. Экспортировать именно в `index.html` внутри отдельной новой папки, например `AbyssLoop_WebExport`.
5. Не переименовывать `index.html`, `.js`, `.wasm` или `.pck` по отдельности.

## Локальный браузерный запуск

Когда `AbyssLoop_WebExport/` содержит `index.html`, `.js`, `.wasm` и `.pck`, запустите локальный тест:

```bash
python3 tools/web_browser_smoke_test.py \
  --directory ../AbyssLoop_WebExport \
  --screenshot ../AbyssLoop_Web_Smoke.png \
  --report ../AbyssLoop_Web_Smoke.json
```

Он поднимает временный локальный HTTP-сервер с корректным MIME-типом WebAssembly, запускает Chromium через Playwright, проверяет HTTP-ответ, наличие и размер canvas, поддержку WebGL 2, загрузку JavaScript/WASM/PCK, необработанные JavaScript-ошибки и консоль браузера. Скриншот и JSON-отчёт сохраняются отдельно. Это smoke-тест запуска, не полный игровой тест.

Если нужен интерактивный preview без автоматического закрытия браузера, откройте в другом терминале:

```bash
python3 -m http.server 8000 --directory ../AbyssLoop_WebExport
```

В этом режиме не все Python-версии могут отдавать `.wasm` с MIME `application/wasm`; если игра не стартует, используйте браузерный smoke-скрипт или размещение из следующего раздела.

## Получить публичную ссылку через GitHub Pages

В `.github/workflows/abyssloop-web.yml` добавлен CI-пайплайн. После помещения проекта в репозиторий GitHub:

1. Убедитесь, что основная ветка называется `main`.
2. В настройках репозитория откройте Pages и установите Source = **GitHub Actions**.
3. Запустите workflow `Abyss Loop Web Export and Browser QA` или отправьте коммит в `main`.
4. Сначала должны пройти экспорт и browser smoke test; только затем workflow публикует Web-сборку в Pages.
5. URL Pages и артефакт с QA-скриншотом появятся в результате workflow. Публичный URL нельзя предсказать до появления репозитория/owner.

Для itch.io альтернативный путь — выбрать тип страницы HTML Game и загрузить ZIP, в корне которого лежит `index.html` со всеми созданными Godot файлами рядом: https://itch.io/docs/creators/html5

## Как продолжать QA

После успешного экспорта сначала проверить стартовую сцену и базовое взаимодействие в Chromium. Затем вручную проверить старт экспедиции, размещение карточки на узле и ландшафте, подсказки, бой, статусные эффекты, событие, босса, возврат и сохранение. Повторно открыть страницу и проверить восстановление данных, затем прогнать те же сценарии в Safari на iPhone. Chromium-smoke не заменяет эти проверки и не доказывает поведение на iOS.
