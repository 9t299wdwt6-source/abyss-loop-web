# Abyss Loop — продолжение дорожной карты: этап 62

**База:** Prototype 61.0 RC7 (`0.61.0`). Предыдущие ZIP-сборки остаются неизменными. Этот документ дополняет `ROADMAP_CONTINUATION_STAGES29-61_RU.md`, не заменяя закрытые этапы.

## Этап 62 — стабилизация QA-процесса и runtime-приёмка

### Выполненная часть в текущем hotfix

- Статическая регрессия показала, что параллельный прогон иногда останавливался после части тестов, хотя оставшиеся тесты проходили при прямом запуске. Это трактуется как проблема устойчивости QA-runner, а не как доказанный дефект игровых систем.
- Добавлен `tools/test_process_runner.py`: каждый тест запускается в собственной process group; по тайм-ауту завершается дерево процессов, включая потомков, удерживающих захваченный stdout.
- `tests/run_static_suite.py` сохраняет параллельный режим до четырёх workers по умолчанию; `ABYSS_LOOP_TEST_WORKERS=1..4` позволяет ограничить параллелизм. Оба Windows launcher задают максимум четыре workers только если пользователь не указал иной режим.
- Добавлен `tests/static_suite_runner_regression.py`: проверяет обычный запуск, предсказуемый тайм-аут и завершение дочернего процесса, который удерживает stdout.
- Windows launchers по умолчанию используют до четырёх workers; значение можно ограничить переменной `ABYSS_LOOP_TEST_WORKERS`.
- Новые инструменты и регрессия включены в релизные требования упаковщика и независимого preflight.

### Что проверено здесь

- Базовый RC7 архив распакован; CRC прошёл; в архиве ровно одна корневая папка `AbyssLoop/`.
- В текущем окружении полный новый набор был выполнен отдельным процессом: **70/70 PASS на момент этапа 62A**, без ошибок и тайм-аутов. Обрыв прежних интерактивных вызовов не считался результатом теста; после исправления fixture для нового roadmap-документа набор повторно завершился полностью.
- Функциональный тест для процесса-потомка отдельно проверил, что timeout закрывает группу процессов и не оставляет захваченный stdout открытым.
- Godot 4.7.2 в текущем Linux-окружении отсутствует. Попытка получить двоичный файл через сетевую загрузку не удалась, поэтому импорт сцен, компиляцию GDScript, запуск игры и сквозное сохранение здесь подтвердить нельзя.

### Ворота этапа 62 — текущие статусы

1. ✅ Полный `tests/run_static_suite.py`: **71/71 PASS** без `FAIL`/`TIMEOUT`; время 43,34 с.
2. ✅ `tools/release_preflight.py --expected-version 0.61.0 --require-static-report`: **7/7 PASS**. Упаковщик запущен дважды; оба ZIP совпали по SHA-256; независимый аудит архива — **7/7 PASS**.
3. ⏳ Открыто: на Windows с официальным Godot 4.7.2 stable запустить `RUN_RELEASE_GATE_WINDOWS.bat`; все семь ворот должны быть PASS с актуальным source fingerprint.
4. ⏳ Открыто: ручная приёмка UI и игрового цикла по чек-листам Prototype 59–61, включая продолжение старого сохранения, новую экспедицию, событие, размещение тайла, бой, поражение, возврат и проверку отсутствия двойной награды.

**Статус этапа 62: В РАБОТЕ.** Статический QA-набор и release preflight подтверждены, но runtime не подтверждён, и этап не считается закрытым до настоящего прогона Godot на целевой Windows-среде и ручной приёмки. Версия игры остаётся `0.61.0`; этот hotfix улучшает только надёжность проверок и не меняет механику игры.

## Следующий шаг

После зелёного набора и успешного Godot gate перейти к этапу 63 из утверждённого плана: исправлять только дефекты, воспроизведённые в runtime, с тестом на каждый дефект. Не добавлять новые игровые подсистемы до закрытия этой приёмки.


### Этап 62B — тайм-ауты runtime release gate

- `tools/run_runtime_gate.py` больше не использует `subprocess.run(timeout=...)` для запуска этапов gate: он делегирует запуск общему `tools/test_process_runner.py`, который изолирует процесс и завершает дерево процессов по тайм-ауту.
- Добавлена `tests/runtime_gate_process_cleanup_regression.py`: реальные процессы проверяют обычный выход, сохранение ненулевого exit code/вывода и тайм-аут с потомком, который наследует stdout.
- Регрессия включена в `tools/release_preflight.py` и `tools/package_release.py`; контракт релиза и архивная регрессия дополнительно проверяют её наличие.
- Логика игры, схема сохранений, имя профиля и версия `0.61.0` не менялись. Это исправление QA-инфраструктуры, не новый игровой релиз.
- Локальная функциональная регрессия: **3/3 PASS**; искусственный зависший процесс и потомок завершены примерно за 2,5 секунды, без зависания захваченного stdout.

**Статус этапа 62 остаётся В РАБОТЕ:** Godot 4.7.2 stable по-прежнему недоступен здесь. Нельзя объявлять пройденными импорт, компиляцию GDScript, запуск главной сцены, игровой smoke, save regression или expedition integration audit.
