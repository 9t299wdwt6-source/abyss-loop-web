# Stage68C — подготовка Web-экспорта и браузерной приёмки

## Цель

Подготовить воспроизводимый путь, чтобы Abyss Loop можно было запускать из браузера по URL и регулярно проверять после последующих изменений. Stage68C: runtime не подтверждён; это не является подтверждённым Web build: фактический экспорт в доступном окружении заблокирован сетью.

## Изменённые и добавленные материалы

- `export_presets.cfg` — пресет Web для Godot 4.7.2: `GL Compatibility`, single-threaded Web runtime, выключенная поддержка native extensions, responsive canvas и экспериментальная виртуальная клавиатура.
- `tools/export_web.sh` — Linux x86_64 helper с загрузкой официального Godot 4.7.2 stable и экспортных шаблонов, проверкой SHA-256, импортом проекта, экспортом `index.html` и preflight.
- `tools/web_export_preflight.py` — два независимых режима: проверка исходников и проверка реально созданного Web-артефакта.
- `tools/serve_web_export.py` — локальный HTTP-сервер с корректным `application/wasm` MIME и localhost по умолчанию.
- `tools/web_browser_smoke_test.py` — автоматизированная проверка Chromium/Playwright; дополнительно проверяет поддержку WebGL 2, runtime-ресурсы, MIME WASM, canvas и ошибки браузера. Для headless Linux включена программная WebGL-конфигурация SwiftShader.
- `.github/workflows/abyssloop-web.yml` — CI, который загружает официальные шаблоны с верификацией SHA-256, импортирует проект, экспортирует Web, запускает браузерный smoke test и публикует результат в GitHub Pages только при успехе.
- `README_WEB_RU.md` — инструкции для локального экспорта и GitHub Pages.
- `tests/web_export_readiness_regression.py` и дополнения к `tests/release_preflight_regression.py` — регрессии конфигурации и обязательных документов.

## Проверки

Исходный Web-preflight выполнен: 7 из 7 проверок не имеют статуса FAIL; одна из проверок остаётся предупреждением, связанным с debug-only clipboard API. Статические тесты проверяют, что проект не использует C#, использует совместимый рендерер, содержит Web preset, сохраняет данные через `user://`, а preflight не пропускает экспорт без `index.html`, `.js`, `.wasm` или `.pck`.

Godot 4.7.2 и export templates не были получены в контейнере из-за сетевого/DNS ограничения. Нативный запуск и компиляция скриптов не выполнены. Chromium здесь запускается, но системная политика блокирует переходы на localhost; следовательно, настоящего браузерного smoke-test проекта нет. Это ограничение окружения, а не установленная ошибка игры.

## Как получить публичную ссылку

После загрузки проекта в репозиторий GitHub и включения Pages с источником GitHub Actions workflow автоматически собирает и тестирует Web-версию. При успешном результате job `deploy` публикует сайт; URL показывается в результатах `deploy-pages`. Конкретный адрес нельзя назначить заранее: он определяется именем репозитория, владельцем и настройками Pages.

## Риски и границы

- Нельзя считать проект компилируемым для Web, пока первый экспорт не выполнен Godot 4.7.2.
- WebGL 2 должен быть доступен и на целевом браузере; desktop CI не заменяет тест на iPhone.
- Сохранения через `user://` зависят от браузерного хранилища и origin. Сброс данных сайта может удалить локальный прогресс.
- CI smoke-test проверяет запуск, ресурсы, canvas, ошибки JS и WebGL 2, но не подтверждает прохождение игрового цикла. После появления URL нужно отдельно проверить управление, размещение тайлов, бой, события, босса и save/load.
- Баланс и игровая логика не менялись.

**Вывод:** Web export pipeline подготовлен и включён в обязательные исходники/архив. Runtime не подтверждён; публичной ссылки пока нет.
