# Руководство по добавлению контента

Контент хранится в реестре `scripts/core/content_registry.gd`, а правила отображения/поведения — в соответствующих системах. UI не должен самостоятельно начислять награды или вычислять боевые параметры.

## Новый противник

Добавьте новый уникальный ключ в `ENEMIES` с полями `name`, `hp`, `attack`, `defense`, `attack_interval`, `xp`, `scrap`, `crystal`, `role` и понятными `behavior_hint`/`ability_text`. Для специального бонуса защиты укажите необязательное `defense_bonus_after_loop`. Выбираемые генератором роли должны уже поддерживаться `EnemySystem`; новый ID после этого автоматически попадёт в обычные встречи. Добавьте тест нового определения и проверьте генерацию в Godot.

## Новый босс

Добавьте запись в `BOSSES`: базовые параметры, `special_name` и массив `phases`. У фаз должны быть уникальные понятные названия, порог здоровья от 0 до 1, `attack_multiplier`, `defense_bonus`, `attack_interval`, `special_every` и `telegraph`. Пороги идут по убыванию, первая фаза начинается с 1.0. Генератор выбирает босса из всех зарегистрированных IDs по порядку, а не по жёстко заданным названиям.

## Новый тайл / комбинация

Для тайла задайте `name`, `short`, `kind`, `color`, `description`. Для синергии задайте уникальный `id`, `trigger_tile`, `neighbor_tile`, карту `effects` и описание. Типы эффектов должны обрабатываться `TileSystem`; неизвестный эффект не добавляет механику автоматически.

## Новое событие

Событие требует `name`, `narrative`, `weight`, `min_loop` и минимум двух `choices` с уникальными `id`, `title`, `description` и словарём `effects`. Последствия реализуются в `ExpeditionManager` и должны быть идемпотентны при сохранении/загрузке. Для цепочек используйте флаги, а не индекс интерфейсного элемента.

## Исследование, цель, перк

- `BASE_RESEARCH`: цена, массив `prerequisites`, словарь `effects`; все зависимости должны ссылаться на известные IDs и не образовывать циклов.
- `EXPEDITION_OBJECTIVES`: тип цели, цель больше нуля и неотрицательная награда.
- `PERKS`: уникальный ID, максимальное число стаков от 1 и эффекты, агрегируемые `ProgressionSystem`.

После изменения реестра запускайте `python tests/content_registry_validation_regression.py`, `python tests/static_project_check.py` и весь `python tests/run_static_suite.py` (после появления в этапе 23). Затем запускайте `res://tests/smoke_test.gd` в целевой версии Godot. Статическая проверка не заменяет запуск движка.
