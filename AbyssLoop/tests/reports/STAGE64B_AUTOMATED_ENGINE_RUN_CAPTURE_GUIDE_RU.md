# Stage64B CI: автоматическая выборка работы игрового движка

**Тип данных:** `capture_kind=automated_engine_run`. Это not human playtest — не свидетельство ручного прохождения и не источник окончательного решения о балансе.

## Сценарий

GitHub Actions запускает пять экспедиций Abyss Loop на Godot 4.7.2 stable. Для каждого фиксированного seed используется новый изолированный профиль, одна версия игры, стандартная сложность, стандартный модификатор и стандартный режим. Реальный `ExpeditionManager` обрабатывает движение по маршруту, обычные столкновения, события, перки, здоровье, награды и запись результата. Ограничение на 3× и завершение после первого цикла уменьшают время CI.

Сценарий автоматически размещает по одному допустимому тайлу на дороге и ландшафте, выбирает доступное решение события по фиксированной эвристике и принимает первый предложенный перк. Если экспедиция проиграна естественным образом до возврата, записывается поражение. Здоровье героя и врагов, урон, добыча и формулы наград не переписываются ради теста.

## Артефакты CI

После зелёного pipeline архив QA содержит:
- `STAGE64B_AUTOMATED_ENGINE_RUNS.json`: метаданные политики, пять записей с уникальными seed, исходами и реальной телеметрией движка.
- `STAGE64B_AUTOMATED_ENGINE_RUNS_ANALYSIS.md`: офлайн-сводку по этим пяти сценарным прогонам.

Анализатор показывает отдельную группу `automated_engine_run`; её сводка не объединяется с `profile_history`, `manual_playtest` или неизвестным источником.

## Что считается завершением этапа

Эта выборка закрывает только автоматизированную проверку выполнения базового игрового цикла и записи телеметрии. Она не является реальным пользовательским балансным исследованием: решения событий/перков зафиксированы скриптом, режим ограничен первым циклом, а человеческая реакция/стратегия не представлена. Для окончательного Stage64B остаются ручные забеги на пользовательском устройстве, повторы проблемных seed и отдельная оценка длинной экспедиции и боссов. Никакой баланс не меняется автоматически.
