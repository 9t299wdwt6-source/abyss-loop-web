# Журнал дефектов — Abyss Loop

База проверки: `LoopRoguelite_Godot_Prototype_06.zip`.

| ID | Приоритет | Дефект/сценарий | Шаги воспроизведения | Статус |
|---|---|---|---|---|
| QA-001 | Средний | Сохранение при аварийном закрытии | Не подтверждено runtime-прогоном; проверять закрытие в движении/бою/событии | Открыт — требуется Godot |
| QA-002 | Средний | Повторная выдача награды при повторной загрузке | Повторить загрузку перед/после завершения экспедиции и сравнить баланс | Открыт — требуется Godot |
| QA-003 | Средний | Поведение зависимых исследований при недостатке ресурсов | Попробовать покупку до выполнения требований и без цены | Открыт — требуется Godot |
| QA-004 | Средний | Восстановление боя с группой и босса | Сохранить в бою, перезапустить, победить и проверить статистику | Открыт — требуется Godot |
| QA-005 | Низкий | Масштабирование/клавиатурная навигация на нескольких разрешениях | Запустить 1440×900 и 1920×1080, пройти панели клавиатурой | Открыт — требуется Godot |

Отсутствие подтверждённых дефектов не означает, что сценарий доказанно исправен. Статус закрывается только после воспроизводимого теста и повторного прогона регрессии.

## AL-001 — Башенная атака / topology regression

- Severity: Blocker if introduced.
- Expected: башни/турели не наносят боевой урон; бой происходит между героем и противниками.
- Guard: `tests/closed_loop_brand_regression.py` + `tests/smoke_test.gd`.

## AL-002 — Открытый маршрут

- Severity: Critical.
- Expected: `next_index(N-1)=0`, `previous_index(0)=N-1`; визуальная тропа соединяет крайние узлы.
- Guard: `RouteSystem.is_closed_loop`, closed-loop static test and runtime smoke.


## Prototype 28 — профиль пользователя и выпуск

- **Сохранения не должны получать новую папку при каждом номере прототипа.** Исправлено: `application/config/name` стабильно равно `Abyss Loop`, а `config/version` хранит `0.28.0`.
- **Потеря primary при наличии валидного backup.** Исправлено: backup атомарно возвращается в primary; статус отображается пользователю.
- **Перенос прежнего профиля.** Добавлен импорт только из известных имён профилей `Abyss Loop ... Prototype ...` / `LoopRoguelite...` при пустом текущем профиле; исходник не меняется. Требуется runtime-проверка на Windows.
- **Риск тестом сохранений задеть пользовательские данные.** Исправлено в release gate: все Godot smoke/save проверки идут на временной копии с отдельным именем профиля и отключённым legacy-import.
- **Устаревший runtime-отчёт не должен подтверждать изменившийся проект.** Исправлено: runtime gate записывает SHA-256 fingerprint исходников; упаковщик с `--require-runtime-gate` отклоняет отчёт с несовпадающим fingerprint.
- Статические доказательства есть; GDScript runtime, тест профиля реальной сборки и визуальная приёмка остаются открыты до Godot 4.7.2.


## Prototype 41 — экономика предметов

- Добавить к приёмке подтверждение цены улучшения до покупки; улучшение должно повышать основные характеристики без переролла свойства/набора.
- Разбор экипированного предмета блокируется в UI и в authoritative-методе GameState.
- Разбор требует отдельного подтверждения; сохранение должно атомарно фиксировать предмет и возврат ресурсов.
- Статические guards добавлены в `tests/item_upgrade_salvage_regression.py`; фактические операции UI/сохранения остаются **Открыт — требуется Godot** до запуска runtime gate и ручной проверки.


## Prototype 42 — синергии экипировки

- Общий расчёт сборки находится в `InventorySystem.calculate_loadout_stats`: отдельные вклады экипировки и перков объединяются и ограничиваются после агрегации.
- Архетипные синергии активируются только при совпадении слотов и архетипов; за раз активна максимум одна.
- Проверки: `tests/equipment_synergy_regression.py` и `tests/equipment_build_balance_regression.py` (повторяемая упрощённая модель на 12 seed, 8 проверок); runtime fixtures: `tests/smoke_test.gd`.
- UI до/после показывает изменения наборов/синергий.
- Статические проверки — **46/46 PASS**; компиляция и фактическое поведение в Godot — **Открыт — требуется Godot**. Результат offline-баланса — скрининг, не замена игрового прогона.


## Prototype 43 — перераспределение исследований
- Добавлена отдельная запись фактической стоимости покупки для каждого известного исследования. Старые сохранения без этой записи остаются валидными; при сбросе используется текущая цена определения как fallback только для таких старых покупок.
- Сброс доступен только между экспедициями, показывает затронутые узлы и удерживает 20% от подтверждённых вложений, возвращая 80% с округлением вниз.
- Покупка и перераспределение теперь откатывают валюты, узлы и ledger при провале записи.
- Неизвестные текущей версии stable IDs не отбрасываются при загрузке и не удаляются сбросом зарегистрированных узлов; их эффекты остаются неактивными, пока их определения отсутствуют.
- Статические guards: `tests/research_respec_regression.py`. Godot UI, save-failure injection и ручная приёмка **Открыт — требуется Godot**.


## Prototype 44 — альтернативные ветви убежища

- `shelter_branch_regression.py`: независимые entry nodes, единственная принадлежность узла ветви, внутриветочные зависимости и доступность корневых покупок.
- `research_tree_regression.py`: branch-aware UI, next-node preview и причины блокировки.
- `smoke_test.gd`: проверка 4 ветвей, корректных entry nodes и полного покрытия исследований.
- Статические тесты не заменяют Godot 4.7.2 runtime и визуальную приёмку.


## Prototype 45 — экономика длинной кампании

- `tools/economy_campaign.py` читает текущие коэффициенты источников/расходов из `ContentRegistry`, начальные валюты из `GameState`, стоимость построек/исследований и формулу улучшения экипировки.
- Модель сравнивает 4 инвестиционные стратегии × 4 режима кампании с фиксированным seed; отдельный стандартный отчёт охватывает 16 800 смоделированных экспедиций.
- `tests/economy_campaign_regression.py` проверяет привязку к исходникам, целевые уровни инвестиционного плана, детерминизм и неотрицательные остатки.
- Высокий остаток трактуется только относительно конечного списка смоделированных покупок; временный стопор вложений при серии поражений отличён от блокировки бесплатной экспедиции.
- Экономические коэффициенты не менялись без сравнения реальных наград в Godot. Runtime и ручная приёмка остаются **Открыт — требуется Godot 4.7.2**.


## Prototype 47 — журнал кампании

- Журнал хранит максимум 50 кратких записей завершённых экспедиций, с уникальным `run_id`; при повторной записи обновляет существующую строку.
- В сохранение не копируются активные снимки/маршруты; старые профили без поля `expedition_history` читаются как пустой журнал.
- SaveSystem валидирует лимит, ID, исход и ключевые числовые поля; ошибки записи истории откатывают изменённый список в памяти.
- UI убежища показывает все записи или фильтрует только возвращения/поражения; на каждом элементе указаны дата, seed, версия, сложность, счёт и добыча.
- Статические guards: `tests/campaign_history_regression.py`; runtime-normalization/save validation fixtures добавлены в `tests/smoke_test.gd`. Проверка UI, реальной перезагрузки и отказа записи остаётся **Открыт — требуется Godot 4.7.2**.


## Prototype 49 — матрица content 1.0

- `content_v1_matrix_regression.py` фиксирует 20 категорий / 108 stable ID, обязательные поля, ссылки, синергии, дерево исследований, события/флаги и предметные архетипы.
- `tests/fixtures/content_v1_stable_ids.json` предотвращает незамеченное удаление или переименование ID. Разрешённое изменение manifest требует ручного ревью/миграции.
- `tests/reports/CONTENT_V1_READINESS_MATRIX_RU.md` отделяет PASS данных от неполного индивидуального арта, локализации и незапущенного runtime.
