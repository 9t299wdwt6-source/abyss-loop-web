# Abyss Loop — дорожная карта после этапа 76

**Текущая функциональная итерация:** Stage 76 — contextual biome loot and tactical card exchange.  
**Идентификатор проекта:** Prototype 61 RC7 / `0.61.0`.  
**Статус:** статический набор 103/103 PASS; Godot runtime остаётся отдельным незакрытым воротом.

## Зафиксированные изменения Stage 76

- Тематические аффиксы оружия влияют на урон и шанс соответствующего биомного трофея.
- Бонусы трофеев учитываются только для надетых предметов, имеют верхний предел и отражаются в описаниях.
- Предпросмотр и фактический расчёт трофея используют один источник формулы.
- Рука карт поддерживает однократный за цикл обмен выбранной карты за 1 кристалл.
- Обмен блокируется в опасных/незавершённых состояниях и откатывается целиком при ошибке сохранения.
- Интерфейс показывает доступность обмена и активную подготовку добычи.

## Следующие приоритеты

### Stage 77 — информативная рука карт и прогноз размещения

1. Улучшить превью выбранной карты: тип размещения, сектор маршрута, текущая синергия, новые синергии при установке, изменение риска/награды и причины запрета.
2. Явно отличать «карта в руке», «доступна для дороги» и «доступна для ландшафта» до клика по полю.
3. Проверить, что выбор карты остаётся стабильным после перерисовки руки, отказа размещения и загрузки snapshot.
4. Добавить независимые source guards и Godot smoke fixtures для прогноза до/после размещения, включая соседние комбинации в обратном порядке установки.

### Stage 78 — предметные сборки и цикл добычи

1. Связать редкость предмета с реальными контекстными источниками добычи, биомом и риском, не ломая гарантированные предметы боссов.
2. Показывать сравнение нового предмета с экипированным до надевания; не менять экипировку автоматически.
3. Показывать, что теряется/сохраняется при поражении, возврате и заполненном рюкзаке; не допускать потери предмета при транзакционной ошибке.
4. Проверить обратную совместимость старых предметов и сохранений.

### Поздняя сквозная приёмка

- Не запускать отдельную браузерную проверку после каждой механики.
- После завершения взаимосвязанных изменений выполнить один общий проход: статические тесты → Godot 4.7.2 import/compile → smoke → сохранения → полный цикл экспедиции → босс/поражение/возврат → Web export и браузерная проверка при необходимости.
- Не утверждать runtime PASS без отчёта, соответствующего точному fingerprint исходников.

## Правила совместимости

Сохранять стабильные ID, схему сохранений и имя приложения. Старые сохранения должны принимать отсутствующие новые необязательные поля через нормализацию. Упаковывать проект в ZIP с ровно одной верхней папкой `AbyssLoop/`, хранить предыдущие сборки отдельно.
